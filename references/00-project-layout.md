# 项目文件组织与命名规范（P0 定，全程遵守）

> 写论文是**串行管线**，目录与文件名的**序号必须体现阶段位置**，做到"看文件名即知在第几阶段"。
> 本规范必须**同时**满足 orchd 约束与本 skill 约束（§4 给出联合检查表）。

## 1. 命名规则

1. **目录**：`NN-<域>`，NN 为两位阶段号（下表）。
2. **文件**：`<NN><ii>-<kebab-语义>.<ext>`，NN 与所在目录同号，`ii` 为域内两位序号（起始号不强制 00/01，以该项目首产物实际形态为准；同一域内连续、新增用下一位、不重排）。
3. **语言**：文件名一律 **ASCII kebab-case**（跨平台、git、LaTeX、shell 全安全）。**中文仅允许**出现在 `10-data/raw/**` 的原始件（保留原名，另在 `10-data/raw/MAPPING.md` 登记中英对照）。
4. **工具约定名不加号**：`SKILL.md`、`README.md`、`.gitignore`、`.orchd/**`、引擎跟踪的 `ROADMAP.md`。
5. **派生物必须在文件头标注**：LaTeX（`% GENERATED — do not edit`）、由脚本生成的 md（`<!-- generated by <script> -->`）。

> `00-DECISIONS.md` 与 README 状态节）。

## 3. 与 orchd 的对应（声明路径怎么写）

- 任务声明的 `files_to_read` / `files_to_edit` 一律用**项目根相对路径**（如 `30-manuscript/sections/31-introduction.md`）。
- 一个任务**一个主产物**：任务 id 与产物名同源（`task-write-introduction` → `31-introduction.md`），便于"任务→产物"双向定位。
- `files_to_edit` ≤5（超触发 E029）；连带改动的既有文件**直接写入 files_to_edit**，不用 `exempt_files`。
- `verify_command` 用编号后的路径：`python 70-tools/70-verify.py task-<id>`（引擎不关心目录名，只要求命令可执行）。
- **`.orchd/**` 只由引擎写**；引擎自带的系统设计文档归 `.orchd/docs/`，**不要**在项目根另开 `docs/`（本项目 paper1 就出现了 `docs/` vs `documents/` 同名混淆）。

## 6. 实施实证（paper1 迁移，2026-09-24，务必遵守）

**paper1 的最终形态两处例外**（其余全部按 §2 编号）：
- **`scripts/` 保留目录名**（不叫 `70-tools/`）：22 条历史任务的 `verify_command` = `python scripts/verify.py task-<id>`，而**终态任务不可改执行字段**，改名即永久失去"历史任务 verify 可重跑"这一回归能力；`verify.py` / `verify_manifest.json` 两个契约文件名同样冻结，其余脚本编号化（`72-*` 生产、`78-scratch`、`79-archive`）。
- **`docs/` 不动**（引擎 vendor 的 system-design），项目文档一律进 `00-admin/`。

**引擎约束（迁移中实测，违反会卡住）**：
1. **注册期禁目录式声明**（E003：`intake.md step 4`），`exempt_files` 同样拒绝；而**钩子只对以 `/` 结尾的声明做前缀匹配**（`gitops/hook.py:632`）⇒ 两者语法互斥，"批量路径变更"无法在声明域内表达。批量迁移只能：**最小声明 + 单次 `--no-verify`**（须用户授权并在提交信息/交付说明/审查意见三处披露）。
2. **amend 只在 main**（E007 红线 7）；flat 布局下主工作树就是同一目录 ⇒ 补登声明必须**先切回 main**，再用 `git show main:.orchd/_master.json` 取内容写回任务分支并提交（该文件属固定资产豁免）。`proxy.py` 文档承诺的"task 分支 `merge main` 放行"在实测中**不生效**。
3. **E010 守卫比对的是 git 的"引号 + 八进制转义"路径形态**（如 `"20-lit/…Core\342\200\220Shell…pdf"`），不是原始 UTF-8。凡路径含非 ASCII 或空格，声明须按该形态补登；工具链一律用 `git … -z` 取路径（**绝不要 `.split()`**，否则含空格的路径被拆碎）。
4. **claimed 任务禁 `--remove-files-to-edit`**、**completed 任务禁改执行字段** ⇒ 被污染的声明**无自愈通道**；补登前务必确认路径正确，宁可分批也不要一次性拼字符串。
5. 声明路径**数量可达数百条**（schema 无 maxItems），E029 只是告警；但每条都必须与实际变更逐一对应，否则 `done` 反复被 E010 拦（本轮共 6 轮补登才收敛）。

**路径替换的两个硬规则**（血的教训）：
- **幂等**：前缀替换必须带负向后顾（如 `(?<!20-)lit/`），否则 `("lit/" → "20-lit/")` 会把刚生成的新前缀再前缀一次——本轮因此把 42 条 `local_pdf` 值累积成 8 层前缀，需全库折叠修复。
- **值级自检**：迁移自检不仅要查"文件路径是否残留旧前缀"，还要查**文件内部的值**（库字段、清单、md 提及）；只查前者会漏掉最隐蔽的损坏。

**迁移任务的最小自检集（verify_command 必须覆盖）**：旧目录无残留文件 → 全部声明路径存在 → 契约文件保号 → **全量历史任务 verify 逐个 PASS**（pending 任务因产物未生成而 FAIL 属预期）→ 引擎/宿主目录（`.orchd/ docs/ .workbuddy/`）零改动。
